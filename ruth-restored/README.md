## 原版特色怎样保留并改善

1. 背景：直接复用原SVG里的日落和海面图像，未更换成其他素材。统一深绿遮罩；内容放在不透明深绿卡片上，避免字贴在照片上读不清。
2. 精力圆：继续使用橙色水波的视觉语言；以“units remaining”明确标注数值，旁边同时给出Used和Daily budget。不是完成目标或健身奖励。
3. 时间轴：每个日期使用一致的触控单元，选中日期为浅绿，同时显示当天记录摘要。History按日期并列展示活动消耗和症状，16页展示选中1Oct后的历史快照，体现可比较不同日期。
4. 语音：恢复原来底部麦克风、文字输入区和加号。点击麦克风录音；录音结束后可检查并修改文字、选择三类精力消耗，再确认保存。语音是手动输入的替代方式，能降低打字负担；不自动判断症状或消耗。
5. 称呼：首页为Hi, Ruth，按作业用户Ruth的拼写，不使用Huth。
6. 按钮：主按钮统一浅绿底深绿字，次按钮统一深绿底和边框。核心操作52高，成组记录入口等宽；小型选择、返回和麦克风目标至少44×44。
7. 排版：页面440×956，主内容左右24留白。层级、卡片圆角、字体和间距统一。字体DejaVu Sans；正文通常14–18，关键数据22–50，少数非核心状态／小标题12–13。

作业没有固定页数。原六页提供入口，但没有把语音、计划调整、保存及撤销机制完全展示。因此只补充相关状态，不搭建无关功能。

## 设计限制与启发式审查

- 没有打卡奖励、徽章、连续活动目标、历史最佳、鼓励突破上限或增长建议（DC1）。
- 不把休息、停止、糟糕症状表述为失败；不要求“补回来”（DC2）。
- 常规文字记录一屏完成，症状直接选择，语音为可选方式；转写确认用于防止识别错误，不强迫所有人走语音流程（DC3）。
- 字和主要控件可见边界进行了对比度检查，所有关键信息有文字，不依赖颜色；无闪烁或动画（DC4）。
- 单位是个人估计；历史可能模式不证明因果，不诊断、不声称医疗安全（DC5）。
- 一致性：按钮、选择、卡片、日期单位相同。
- 反馈和闭合：记录、症状、预算和计划均有完成状态；主要结果提供Undo。
- 防错：语音必须确认；计划估计与已经记录的消耗分开；超过额度明确Over by，不显示负数剩余或成绩奖励。
- 用户掌控：取消录音／保存、保留计划、重新选择时间、自行修改额度。
- 减少记忆：预算内展示近期记录，历史同屏展示活动和延迟症状。

## 验证与修正证据

已解析16个SVG、渲染各页并合并16页PDF，检查页面尺寸、文字边界和可见非叠层文字碰撞。预算弹窗故意遮盖变暗Home，保存横幅替换旧计划入口；这些叠层单独进行了视觉查看。

发现并修改：时间轴选中日期最初超出卡片下缘，重新排齐；历史列标题拥挤，调整列间距；保存后时间轴和近期活动最初是旧数据，改为同步25或25/80；背景最亮像素下对比初检不足4.5，加深遮罩。

正文#F4F1E8在卡片#19362F上11.55:1；次文字#C4D5CA为8.52:1；主按钮深字在浅绿底上10.63:1；精力圆深字对橙底7.64:1；控件边界对卡片3.12:1。原图片所有像素经遮罩后，主要浅色正文保守最低4.88:1。测试的是标准对比与静态布局，不是实机低亮度／用户／临床测试；导入后应在自己的手机或低亮度屏幕检查。

没有实现语音功能或交互。数据示例不代表医学阈值。原始课程手册未提供，要求依照用户上传的整理文本核对。

## Figma 导入及最终PDF

1. 新建Page，命名Ruth — Restored。
2. 将screens文件夹中的16个SVG拖入画布。先保留旧设计作备份。
3. 每个对象分别Frame selection，检查440×956；按01到16排列、命名。
4. SVG使用DejaVu Sans文字，导入行为可能转换轮廓或替换字体，检查后再导出。SVG不保留Auto Layout或组件关系。
5. File → Export frames to PDF，一次导出多个Frame。检查16页齐全、文字未裁切、顺序正确，再按课程要求交Canvas。

## 在GitHub删除文档

打开仓库中要删除的文件（例如旧README_交付说明.md），点击文件右上角…或编辑按钮旁的下拉菜单，选择Delete file；然后Commit changes，将删除提交到main。不要只删本地副本，那不会影响GitHub。

如果看不到Delete file，确认已登录对该仓库有写权限的账号。Web界面适合逐个删除文档；批量清理目录可用GitHub Desktop或Git。在未得到明确要删除哪些目录的指示前，本次保留旧版，不替用户删除。
